# Keitaro Campaign Manager

Обёртка над Keitaro на FastAPI и SQLAlchemy с интерфейсом на HTML, CSS и JavaScript.
Реализованы создание кампаний и редактор офферов с черновиками и локальным архивом.

## Текущее состояние: этап 3

- Настройки через переменные окружения и `.env`.
- Клиент Keitaro Admin API с таймаутами и обработкой ошибок.
- Получение доменов, групп кампаний, источников и офферов.
- База SQLite, журнал операций и миграции Alembic.
- Проверка названия: обязательный префикс `test_kozina_`.
- Автоматические проверки API-клиента, конфигурации и миграций.
- Форма создания кампании с двумя потоками и проверкой справочников.
- Проверка реальных настроек перед включением кампании.
- Сохранение результатов и защита от повторного создания по ID запроса.
- Сверка неопределённого результата с Keitaro без повторной записи в трекер.
- Редактор: Fetch, Add, Remove, Bring back, Cancel и Push to KT.
- Черновики и архив офферов сохраняются в SQLite и переживают перезапуск.
- Закрепление долей и целочисленное распределение оставшегося трафика.
- Проверка внешних изменений и версий черновика перед публикацией.

## Установка

Нужен Python 3.11 или новее. Команды выполняются из корня проекта.

```bash
git clone https://github.com/Kozina-Kate/keitaro-campaign-manager.git
cd keitaro-campaign-manager
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock
python -m pip install -e . --no-deps
cp .env.example .env
```

В `.env` укажите корневой HTTPS-адрес трекера **без `/admin`** и существующий
API-ключ из профиля Keitaro → «API ключи»:

```dotenv
KEITARO_BASE_URL=https://your-tracker.example
KEITARO_API_KEY=your-api-key
KEITARO_TIMEOUT_SECONDS=20
DATABASE_URL=sqlite:///./app.db
```

`.env`, база и виртуальное окружение исключены из Git. Ключ передаётся только
сервером в заголовке `Api-Key`; в ответах приложения и браузерном коде его нет.
Не публикуйте `.env` и не вставляйте ключ в README или URL.

## Миграции и запуск

```bash
alembic upgrade head
uvicorn app.main:create_app --factory --reload --host 127.0.0.1
```

- Форма создания: <http://127.0.0.1:8000/>.
- Редактор офферов: <http://127.0.0.1:8000/editor>.
- Документация приложения: <http://127.0.0.1:8000/docs>.
- Готовность базы: `GET /health` — `200`, если таблица журнала доступна;
  `503`, если необходимо проверить БД или применить миграции.
- Справочники Keitaro: `GET /api/reference-data` — списки ID и названий.

При обновлении также выполните `alembic upgrade head`: миграция `0002` добавляет
данные операции создания, `0003` — потоки, офферы, черновики и архив редактора.

## Создание кампании

1. Откройте главную страницу и дождитесь сообщения «API подключён».
2. Введите название с префиксом `test_kozina_` и код страны, например `AU`.
3. Выберите оффер, домен, группу кампаний и источник из справочников.
4. Нажмите «Создать кампанию». Приложение создаст выключенную кампанию,
   последовательно добавит два потока, проверит настройки и включит кампанию.
5. В результате появятся ID кампании и потоков, ссылка на кампанию и её настройки.

Режим ротации — `position`. Первый обычный поток содержит фильтр `country`
в режиме `accept` и HTTP-редирект на `https://www.google.com/`. Второй обычный
поток не содержит фильтров или лендингов и направляет на выбранный оффер с долей
100%. Поэтому первый поток имеет приоритет, а второй принимает остальных.

Форма сохраняет ID запроса в текущей вкладке браузера. Повторный запрос с тем же
ID не создаёт новую кампанию. Не используйте другой ID для автоматического
повтора после таймаута: операция могла выполниться в Keitaro.

Статусы журнала: `pending` — выполнение не завершено, `succeeded` — результат
проверен, `failed` — создание не выполнено, `partial` — частичное выполнение
или неопределённый результат. При ошибке приложение показывает известные ID.
Кампания не включается до проверки двух потоков; если ошибка произошла уже
после отправки команды включения, она может быть активна.

Кнопка «Проверить статус» получает сохранённую операцию и при необходимости
повторно читает настройки из Keitaro. Если активная кампания полностью совпадает
с запросом, операция отмечается успешной. Сверка не создаёт и не меняет кампании.
Если создание завершилось до получения ID или остался неполный набор потоков,
нужно проверить кампанию вручную. Удаление и автоматическое восстановление
незавершённых кампаний пока не реализованы.

### API создания

`POST /api/campaigns` принимает JSON:

```json
{
  "request_id": "e6cbcaad-739c-4c5e-a27d-3c2ce90dd430",
  "name": "test_kozina_campaign1",
  "country_code": "AU",
  "offer_id": 1,
  "domain_id": 1,
  "group_id": 1,
  "traffic_source_id": 1
}
```

ID `1` в примере условные — используйте доступные ID из `/api/reference-data`.
Для новой операции нужен новый UUID; для повтора той же — прежний.
Статус: `GET /api/operations/{request_id}`.
Сверка с Keitaro: `POST /api/operations/{request_id}/verify`.
Повтор с другим содержимым или ещё не завершённой операцией получает `409`.
Некорректные данные получают `422`, частичная ошибка создания — `502`.

## Редактор офферов

1. Откройте `/editor`, введите ID кампании и нажмите **Загрузить из Keitaro** (Fetch).
   Из результата создания можно перейти сразу по ссылке «Редактировать офферы».
2. Для потока с офферами найдите оффер по ID или части названия, выберите результат
   и нажмите **Add**. Существующий оффер повторно добавлять нельзя.
3. **Remove** делает оффер серым и выставляет 0%. **Bring back** возвращает его.
   Сами объекты офферов в Keitaro не удаляются — меняется связь с потоком.
4. Изменённый поток выделяется жёлтым. **Cancel** возвращает опубликованное
   состояние, удаляя связи, добавленные только в черновике.
5. **Push to KT** отправляет список активных офферов выбранного потока в Keitaro.
   Результат проверяется повторным чтением. Удалённые офферы остаются в архиве
   локальной базы и доступны для восстановления.
6. При следующем Fetch известные офферы, исчезнувшие из Keitaro, тоже переходят
   в архив. Сам Fetch не меняет данные трекера.

Без Fetch страница восстанавливает сохранённое локальное состояние. Кнопка
«Обновить сохранённое состояние» читает SQLite, не заменяя черновик данными API.
Fetch при неопубликованном черновике блокируется: сначала опубликуйте или отмените
его. При неопределённой публикации сначала проверьте её результат.

Потоки без редактируемого списка офферов показываются без разбора действия
и фильтров. В этом тестовом приложении редактируются только кампании с префиксом
`test_kozina_`. Остальные кампании защищены проверкой на сервере.

### Доли трафика

Введите целое число 0–100 и нажмите «Закрепить долю». Закреплённая доля
сохраняется при добавлении и удалении других офферов. «Открепить» возвращает
автоматическое распределение.

Оставшиеся проценты делятся между незакреплёнными активными офферами. Остаток
от округления по одному проценту получают офферы в порядке возрастания ID:
например, 100% на троих — 34/33/33. Если закреплено 25%, двум остальным
достанется 38/37. Сумма закреплённых долей не может превышать 100%. Если
закреплены все офферы, сумма должна быть ровно 100%.

Удаление последнего активного оффера допустимо в черновике, но такой поток
нельзя опубликовать: сначала добавьте или восстановите оффер. При удалении
закреплённого оффера его закрепление снимается; Cancel восстанавливает его.

### Конфликты и таймауты

Каждое изменение передаёт текущую `revision`; устаревший запрос получает `409`.
Перед PUT приложение сравнивает офферы и схему потока с последним снимком.
Если они изменены напрямую в Keitaro, публикация блокируется. Отмените черновик
и выполните Fetch, чтобы загрузить актуальные данные.

После таймаута записи редактор блокирует повторную публикацию. Нажмите
«Проверить публикацию»: выполняется GET в Keitaro. Если получен ожидаемый список,
черновик становится опубликованным; если остался исходный — можно повторить
публикацию вручную; при третьем варианте показывается конфликт.
После аварийного завершения процесса проверка незавершённой публикации доступна
через время таймаута API плюс 5 секунд.

PUT отправляет **только `offers`**. Фильтры, действие, лендинги и остальные потоки
не перезаписываются. Keitaro не предоставляет используемому клиенту атомарную
условную запись: внешний редактор может изменить список между проверкой и PUT.
На время публикации избегайте параллельного редактирования того же потока
в админке. Запускайте локальное приложение одним процессом Uvicorn.

### API редактора

- `GET /api/editor/offers?q=...` — поиск доступных активных офферов.
- `POST /api/editor/campaigns/{id}/fetch` — загрузка и синхронизация.
- `GET /api/editor/campaigns/{id}` — сохранённое состояние.
- `POST /api/editor/streams/{id}/{action}` — изменение выбранного потока.

Действия: `add`, `remove`, `restore`, `pin`, `unpin`, `cancel`, `publish`,
`reconcile`. JSON содержит `revision`, для действий с оффером — `offer_id`,
для `pin` — также `share`. Пример:

```json
{"revision": 3, "offer_id": 18813, "share": 25}
```

Добавление/удаление/отмена меняют только локальную БД. Запись в Keitaro
выполняется только действием `publish`; `reconcile` выполняет только GET.

## Диагностика подключения

Проверка подключения без изменения данных (выводится только число записей):

```bash
python -m app.check_connection
```

Ошибки подключения возвращаются с кодами `502`/`504`, отсутствие ключа — `503`.
Необработанные тела ответов Keitaro и секреты не передаются клиенту.
Сервер предназначен для локального запуска; перед размещением в сети потребуется
аутентификация пользователей.

Проверить версию схемы и отсутствие расхождений с моделями:

```bash
alembic current
alembic check
```

Полный откат: `alembic downgrade base`. Он удаляет журнал, черновики и архив;
для рабочей базы сначала сделайте резервную копию.

## Проверки

```bash
pytest -q
ruff check .
```

Тесты не обращаются к реальному Keitaro: ответы API подменяются через HTTPX,
миграции проверяются на временной базе.

Для обновления зависимостей разработчик может использовать
`python -m pip install -e '.[dev]'`. Для повторяемой установки используйте
зафиксированные версии из `requirements.lock`.
