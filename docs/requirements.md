## Создание кампании (следующий этап)

Входные данные: название, двухбуквенный код страны и ID существующего оффера.
Название должно начинаться с `test_kozina_`, например `test_kozina_campaign1`.
Пользователь выбирает существующие домен, группу кампаний и источник из API.
Конкретные ID не фиксируются в исходном коде.

Кампания содержит два потока. Первый перехватывает посетителей из указанной
страны и перенаправляет на `https://www.google.com/`. Второй принимает остальных
и направляет на выбранный оффер. Порядок потоков и режим их обработки должны
обеспечивать приоритет геофильтра.

## Редактор: логика из видео

1. Fetch streams получает потоки кампании. Потоки без офферов отображаются
   без разбора фильтров и действия редиректа.
2. Оффер выбирается через поиск по Keitaro, в том числе по ID.
3. Добавление меняет локальный черновик, поток помечается неопубликованным.
   До Push to KT данные в Keitaro не меняются.
4. Push публикует изменения выбранного потока.
5. Cancel отменяет неопубликованные изменения и удаляет добавленные только
   в черновике связи с офферами.
6. Remove выставляет офферу долю 0 и помечает его удалённым. После публикации
   оффер исчезает из потока Keitaro, но сохраняется в локальном архиве.
7. Bring back возвращает архивный оффер через черновик и публикацию.
8. Повторный Fetch сохраняет известные локальные офферы, удалённые напрямую
   в Keitaro: они переходят в архив и могут быть восстановлены.
9. Долю оффера можно закрепить. При изменении состава активных офферов
   закреплённые доли сохраняются, остаток равномерно распределяется между
   незакреплёнными; итоговая сумма активных долей — 100%.

Проверить до реализации редактора: целочисленное округление (например,
34/33/33), запрет суммы закреплённых долей больше 100%, поведение при удалении
последнего активного оффера и конфликты внешних изменений с черновиком.
Это граничные случаи, явно не определённые видео.

Для редактора нужны дополнительные таблицы снимков потоков, офферов и связей
с опубликованными и черновыми значениями. Журнал операций из первой миграции
не заменяет это хранилище. Их схема будет добавлена отдельной миграцией.

## Проверка доступа — 19 ноября 2026

Существующий API-ключ проверен GET-запросами. На момент проверки получены:
1 домен, 20 групп кампаний, 1 источник, 1 оффер. Это снимок доступности,
а не значения для подстановки в код. Данные в Keitaro не изменялись.

Используемые маршруты: `/admin_api/v1/domains`, `/groups?type=campaigns`,
`/traffic_sources`, `/offers`. Авторизация — заголовок `Api-Key`.

Встроенная документация подтверждает маршруты создания кампаний и потоков,
чтения потоков кампании и обновления потока. Контракты записи необходимо
проверить при выполнении второго этапа на тестовой кампании с нужным префиксом.
